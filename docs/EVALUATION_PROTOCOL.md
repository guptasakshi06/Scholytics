## Questions and fixed comparisons

1. What changes when only image preprocessing changes? Run A, B, C and the nine declared C ablations on exactly the same 52 final-test pages. Hold Tesseract, literal keyword classifier `keyword-1.0`, spatial extraction `spatial-s06-1.0`, field normalization `field-normalization-s06-1.0`, and requirement engine `requirements-s07-1.0` fixed. Save all stage images and actual predictions, including failures. This isolates preprocessing within the implemented pipeline; it does not establish universal OCR superiority.
2. What changes when the keyword classifier is replaced with a learned classifier? On **A only**, compare keyword versus the frozen A-trained `tfidf-lr-s09-1.0` model, with identical OCR, extraction and requirement logic. This is a separate downstream comparison. No branch-specific retraining, transfer of a branch-restricted model to other branches, or attribution of classifier gains solely to DIP is allowed.

A is common ingestion without enhancement. B is grayscale followed by Otsu. C retains the original ordered deskew, CLAHE, median filter, adaptive threshold, then black-ink open/close morphology with identity 1x1 kernel. All exact values are in the config. C's kernel was selected from four predeclared full-pipeline candidates: identity, 1x2, 2x1 and 2x2. The validation selection retained identity. The no-step diagnostics were not candidates in this bounded kernel selection. They are still reported, including any better result.

The 12 variants, in fixed order, are A, B, C, C_no_deskew, C_no_clahe, C_no_filter, C_no_threshold_or_morphology, C_no_morphology, C_gray_only, C_kernel_1x2, C_kernel_2x1 and C_kernel_2x2. Threshold removal also removes binary morphology because its input contract requires a binary image. No-morphology and identity kernel may tie; keep both definitions. Kernels use [height,width], explicit center anchor and open-before-close. Overlay coordinates remain in the declared processed space. No per-page reference-based branch choice is permitted.

## Training and selection

The pre-inference plan tries LR C in {0.5,4,16}, maximum-class probability in {0.3,0.4,0.5,0.6}, and top-two margin in {0.05,0.1,0.2}. Fixed seed is 2026, vocabulary coverage guard 0.1, and the existing multiple-title guard is unchanged. Train OCR alone fits TF-IDF vocabulary and LR weights. The 52 validation pages choose maximum six-class macro-F1, fewer wrong acceptances, stricter probability, stricter margin, then smaller C. Selected C=4, probability=0.6, margin=0.2; model probabilities remain uncalibrated. There is no refit on validation after selection. Manifest labels are training/scoring targets only; filenames, paths, layout, applicant IDs, reference text and reference fields are forbidden model features.

The bounded DIP kernel search uses only 12 pages of validation applicant 10: six labels, clean and one degradation each, excluding erased amount. Choose minimum corpus character edits, then word edits, then original candidate order among full C and its three kernel alternatives. Other validation applicants supply a broader subsequent check, without changing the selected method. All 12 diagnostic variants are saved. On this narrow tuning set, A/B/C had 1/13/19 character edits; removing threshold/morphology had zero. These are development observations, not final results; C superiority is not assumed. OCR modes were held fixed, with no OCR-mode search: English, OEM3, PSM3, timeout20s; PDFs rasterize at300DPI, image inputs retain decoded resolution. Limits are the shared pipeline defaults.

## Inference and metric contracts

The driver passes only image paths and explicit settings to `pipeline.analyze`. It finishes inference for all selected variants and saves predictions before opening text/field/bundle references to score. Page classification uses OCR text, retains all samples and failures, and never substitutes a target class. True-type field extraction is a separately labelled diagnostic after OCR, never an input to document readiness. Single-page inputs allow page and document routing to agree here.

Bundle predictions reuse hash-checked page OCR and call the same `classify`, `extract` and `evaluate` functions as the CLI/UI. They do not call the production engine to construct expected outcomes. Every bundle stays in its applicant component. Scenarios are complete, missing income, category false, category unknown, expected-name mismatch and erased amount. Every applicant supplies six correlated scenarios. Test reference support is ready8, incomplete4, needs_clearer_upload4 and needs_review8. Thus the predeclared false-ready denominator is **16 reference non-ready applications**. This is a support count from reviewed references, not a measured false-ready result. No new final-test duplicate-conflict, corrupt-file, role-conflict or degraded-rotation bundle benchmark is claimed; those remain S07/S08 regressions. All missing/unresolved predictions stay in denominators.

- CER/WER: NFC, casefold, collapse whitespace, including printed synthetic/header/footer text. Report sum of character/word edits divided by total reference characters/words, plus per-page values/distributions. Empty reference rates are null; insertion counts enter corpus totals; empty predictions are retained. Rates can exceed1. Raw text is preserved.
- Classification: fixed five supported types plus other; macro-F1, per-class P/R/F1/support and 6x7 confusion including unresolved. Uncertain/unreadable/error contribute false negatives, never disappear. Per-class zero divisions=0; empty population metrics=null. Other represents observed unsupported content, not guaranteed unknown detection.
- Fields: exact canonical value **and unit and person role** divided by every present reference target, by field and overall. Report value-only diagnostic, missing, wrong non-null, extra, absent and unreadable support separately. Oracle true-type and predicted-type routes remain separate. No fuzzy spelling repair or guessed date/amount is allowed. Existing normalization code/hashes are frozen.
- Readiness: all five named items and all five states retained. Confirmed missing is the positive class for missing P/R/F1. Report application agreement/confusion, requirement-state confusion, completeness agreement, false-ready count / all reference non-ready, and separately false-ready share among predicted-ready. Zero denominators=null/not estimable. Unknown category applicability keeps completeness null. Precedence and requirements are the unchanged fictional `demo-1.1` config, with no invented eligibility/expiry rules.
- Breakdowns: known versus reserved layout, class, clean/rotation/low-contrast/erased amount, and synthetic-only. Preserve supports. No confidence interval or statistical significance claim is predeclared with four test groups. If future work adds intervals, resample applicants/connected groups, never augmentations or bundles as independent units.

## Timing, provenance and execution

Fresh page timings include sequential decode/render/save, original quality, DIP and saved stages, real OCR, keyword classification/extraction/checklist. Model loading and final JSON writes are excluded from shared page runtime; total driver wall time is separately recorded. OCR and preprocessing are separate counters. Cached bundle assembly measures only classification/extraction/rules, not upload latency. Replays are computational reproducibility checks and cannot be described as fresh OCR speed. Caches/OS scheduling are uncontrolled; no cold/warm or speed superiority claim is made. Processor, OS, Python, library and Tesseract versions, page dimensions, input hashes, run IDs and image paths are retained in each run. Interrupted runs are preserved; reused completed batches are settings/input/code checked and explicitly recorded.

From the repository root, use a new output directory for each execution:

```bash
.venv/bin/python scripts/run_experiments.py --config configs/evaluation.json --partition validation --verify-only
.venv/bin/python scripts/run_experiments.py --config configs/evaluation.json --partition validation --suite core --output artifacts/runs/s09-validation-final
.venv/bin/python scripts/run_experiments.py --config configs/evaluation.json --partition validation --suite core --replay-from artifacts/runs/s09-validation-final --output artifacts/runs/s09-validation-replay-final
```
