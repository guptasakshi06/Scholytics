Abstract

ScholarReady is a local system for checking the readiness of printed English scholarship documents. It rasterizes images and PDFs, compares explicit image preprocessing branches, runs Tesseract OCR, classifies document types, extracts evidence linked to tokens, and applies a fictional configurable checklist. Its outputs describe missing or unresolved requirements and requests for human review. Certificate authentication and scholarship decisions lie outside its scope.

The frozen synthetic test contains 52 pages from 24 sources in four applicant groups. Original-image branch A, Otsu branch B and full alternative C produced 3, 22 and 50 character edits over 14,900 reference characters. Exact field matches were 161, 153 and 158 of 164 present targets. All routes produced zero false-ready outcomes among 16 reference non-ready bundles. These results support retaining negative preprocessing findings and conservative uncertainty handling. They do not establish accuracy on real applicants.

Implementation, experiments and this report were prepared with Codex assistance. Actual student review, independent student contributions and sign-off remain unreported. A simple A4 academic format is recommended pending an institutional template.


# 1 Problem scope and objectives

An applicant may supply the wrong document, omit a required item, upload a page whose important text cannot be read, or provide conflicting personal details. A useful readiness checker must distinguish these situations. A plausible OCR value is evidence to inspect, rather than proof that a document is correct.

The course reference identifies Project 042 as a DIP-linked document-readiness application. The substantive contribution here is an inspectable comparison of image processing alternatives and their downstream effects. This report pairs methods and intermediate images with measured OCR, extraction and application outcomes. The preserved course PDF is the source for course requirements, not for invented dataset sizes or performance targets.

Implemented scope

Inputs are local JPG, PNG and PDF documents containing printed English. Supported types are marksheet, income certificate, bonafide certificate, domicile certificate and category certificate. The other class covers observed unsupported examples. An unresolved prediction remains a separate decision state. One fictional scholarship profile requires the first four types and conditionally requires category evidence.

Research questions

First, how do A, B and C change OCR and downstream readiness when the keyword classifier, extraction and rules stay fixed? Second, how does the frozen TF-IDF and Logistic Regression classifier compare with keyword classification on exactly the same A OCR? The second comparison changes a downstream component and cannot be attributed to DIP.

System architecture

Local files enter bounded ingestion and original-image quality measurement. A selected preprocessing branch yields saved stages and geometry. Tesseract returns text, tokens and boxes. Classification selects supported field rules, extraction retains evidence and normalization decisions, and the JSON checklist assembles requirement states and issues. CLI, evaluation and Streamlit use this same pipeline and ApplicationResult schema.

No external applicant-document upload, paid inference API, certificate authenticity test, eligibility calculation or award prediction is part of the implemented workflow. The interface exports JSON and a findings CSV. It does not generate this academic report for applicants.


# 2 Related work and method foundations

Otsu introduced histogram-based threshold selection using class separability [1]. This gives a reproducible global binarization baseline. It does not establish that every document benefits from binarization. ScholarReady compares it directly with original-image OCR on the same held-out pages.

OpenCV documents adaptive thresholding using local neighborhoods [2], local histogram equalization with contrast limiting [3], and morphology with explicit foreground and kernel conventions [4]. These descriptions motivate the alternative chain and its controls. In ScholarReady their utility is an experimental question, assessed using task errors rather than visual darkness alone.

Smith describes the historical Tesseract OCR architecture [5]. That paper provides background rather than a complete description of the installed 5.3.4 engine. Current Tesseract guidance discusses internal preprocessing, resolution, skew, noise and segmentation choices [6]. Internal processing offers one reason why extra external enhancement may fail to improve OCR, but the present experiment does not isolate its internal mechanisms.

The scikit-learn documentation explains TF-IDF text features [7], Logistic Regression classification [8], and leakage risks when preprocessing learns from held-out data [9]. ScholarReady fits both vocabulary and weights on clean training-page OCR only. Applicant and source grouping additionally prevents related variants from appearing in separate partitions.

Position of this project

This is an academic implementation and bounded evaluation of established components, with explicit uncertainty and evidence tracing. It contributes a shared local pipeline, synthetic provenance, grouped partitions, fixed experiments and negative-result analysis. It does not introduce a new thresholding algorithm or claim superiority over commercial document-processing products. No external scholarship-system benchmark was measured.

Source interpretation

References [1] and [5] are research sources. References [2-4] and [6-9] are official implementation guidance. Live OpenCV documentation redirects to a 4.x tutorial while the exercised package is OpenCV headless 5.0.0.93. Algorithm descriptions and the exact tested software environment are distinct. References were checked on 6 November 2026.

# 4 Digital image processing methods

Common ingestion decodes images, applies EXIF orientation, composites transparency onto white, and rasterizes PDF pages at 300 DPI. A preserves that ingested original. Original-image brightness, grayscale standard deviation and Laplacian variance are quality indicators. Their thresholds are heuristics, separate from readiness and completeness.


Branch | Enabled sequence

A | Ingested original, OCR

B | Grayscale, global Otsu threshold, OCR

C | Grayscale, conservative deskew, CLAHE, median filter, Gaussian adaptive threshold, opening then closing, OCR


C parameter | Frozen setting

Deskew search | ±6 degrees, 0.25 degree step, gain floor 1.05

CLAHE | Clip limit 2, 8 by 8 tile grid

Median filter | 3 by 3 neighborhood

Adaptive threshold | 31 pixel block, constant 15

Morphology | Opening then closing, identity 1 by 1 kernel

Otsu selects one histogram threshold [1,2]. Adaptive thresholding compares intensity with a local Gaussian-weighted mean minus the constant [2]. CLAHE limits local contrast amplification [3]. Median filtering replaces a pixel with its neighborhood median. These operations can remove faint punctuation or change strokes as well as suppress artifacts.

Morphology operates on inverted white ink internally [4]. Opening is erosion then dilation, and closing is dilation then erosion. Kernel dimensions are height by width. The identity kernel and no-morphology branch are controls. Fixed alternatives use 1 by 2, 2 by 1 and 2 by 2 kernels. Even kernels can shift strokes through their anchor behavior.

Deskew scores near-horizontal dark text using row projections on a thumbnail and abstains on insufficient or ambiguous evidence. It retains a same-size canvas, so edge content may be cropped. Its homogeneous matrix maps ingested original pixel coordinates to processed coordinates. OCR and field overlays belong on the processed stage. Perspective correction and arbitrary page orientation are outside this method.

# 6 OCR classification and extraction

Tesseract 5.3.4 runs locally with English data, OEM 3, PSM 3 and a 20 second page timeout. The comparison keeps these settings and input pages identical. The wrapper preserves ordered text, token boxes, engine scores, language, version, settings, timing and explicit errors. Engine scores are not calibrated probabilities of field correctness.

The literal-title keyword baseline accepts a single recognized title family, retains ambiguity and recognizes a limited vocabulary for other content. The optional frozen tfidf-lr-s09-1.0 classifier uses word TF-IDF and Logistic Regression with C=4. Validation selected a probability threshold of 0.6 and top-two margin of 0.2. Only clean training A OCR fits vocabulary and weights. No branch-specific retraining occurs.

The classifier consumes OCR text, not filenames, applicant IDs, layouts or annotation labels. Empty, conflicting or weak predictions retain an unresolved state. The class other covers observed unsupported examples and cannot guarantee rejection of every future unknown. Saved model hashes and dependency versions bind the experiment.

Evidence linked field extraction

Label anchors and bounded nearby regions identify candidates using token and line geometry. Type-specific rules normalize dates, names, academic years, amounts and percentages. Each output retains raw text, normalized value or null, unit, person role, page, token references, box, score source and validation reason. Competing candidates remain visible. A generic first-date or first-name fallback is deliberately avoided.


Type | Selected fields

Marksheet | Student, institution, academic year, stated total and percentage

Income | Applicant and guardian roles, income with unit, issue date

Bonafide | Student, institution, course, academic year

Domicile | Applicant, region, issue date

Category | Applicant, printed category, issue date

Monthly amounts stay monthly, ambiguous numeric dates remain unresolved, and missing values never become zero. Extraction coverage is broader than the configured required subset. Optional course errors can lower field accuracy without changing readiness. The separate true-type diagnostic reveals routing effects, even when its counts happen to agree with end-to-end extraction.


# 7 Requirements and uncertainty

The fictional demo JSON defines five named items. Marksheet, income, bonafide and domicile are mandatory. Category applies only when the explicit applicant attribute is true. False makes it not applicable. Unknown preserves a review requirement and an unresolved completeness denominator. No real income limit, certificate expiry or award policy is inferred.


Requirement state | Meaning

satisfied | Resolved supported evidence covers configured required checks

missing | Inventory supports confirmed absence

unreadable | A relevant required value cannot be resolved

needs_review | Ambiguity, conflicts, unresolved inventory or applicability

not_applicable | A condition explicitly resolves to false

An unclassified upload might be the needed document, so it must not automatically establish absence. User-declared type hints remain recorded hints. Conflicting duplicate values require review. Separate incomplete files are not spliced into invented complete evidence. Matching person roles matters: a guardian name must not be compared as an applicant name.

Scores and precedence

Completeness = (100 × satisfied applicable items) / (applicable items)

Only resolved not-applicable items leave the denominator. Unknown applicability or an empty unresolved denominator produces null with an explanation. Quality flags do not increase completeness. A high score cannot override an unresolved required check.

The headline precedence is needs_review, then needs_clearer_upload, then incomplete, then ready. Every item and issue remains visible beneath that headline. Thus several problems can coexist. A processing failure remains explicit rather than silently becoming an empty successful result.

The default checklist requires a documented field subset: see configs/scholarship_demo.json for the complete authoritative definition. Readiness means that this fictional checklist is resolved under the implemented evidence rules. It does not certify truth, identity, eligibility or approval.


# 8 Experimental protocol and metrics

The immutable evaluation-s09-1.1 freeze binds 780 artifacts including configuration, source, model, splits, references and environment. The final test was consumed on 4 November 2026 at 22:11:17 Asia/Kolkata. S10 preserved a fresh all-variant experiment and a separate replay from saved OCR. S12 reports those results without retuning or replacing them.

All 12 preprocessing variants use the same 52 test pages. The primary routes fix keyword-1.0, spatial-s06-1.0 and requirements-s07-1.0. The A learned route adds the separate classification comparison, giving 13 routes. Every route evaluates the same 24 correlated bundle scenarios and 120 requirement items. Failed or empty outputs would remain in denominators. None occurred in this final set.

Definitions

CER = (character edit distance) / (reference characters)

WER = (word edit distance) / (reference words)

Normalization is NFC, case folding and collapsed whitespace, fixed before test inference. An empty-reference rate is null, while its edits remain in corpus totals. Rates can exceed one if insertions dominate.

Classification macro-F1 averages F1 over six fixed classes. Unresolved predictions remain false negatives and appear as a separate confusion column. A missing class has zero F1 under the frozen zero-division convention. Field accuracy requires exact normalized value, unit and person role over every present target. Missing, wrong nonnull, absent, extra and unreadable-reference cases are distinct.

Confirmed missing is the positive label for requirement precision, recall and F1. Other requirement states remain in the complete state-confusion table. Application agreement compares the full four-state headline. False-ready rate = reference non-ready applications predicted ready / all reference non-ready applications. Empty denominators mean not estimable. Raw counts accompany every rate.

Page timings include decode/render, quality, stages and saves, OCR and baseline downstream work, excluding model load and final JSON writes. Bundle timings reuse OCR and measure rules rather than upload latency. Sequential single observations with uncontrolled OS cache cannot establish speed superiority. No confidence interval or significance test is claimed from four groups.

Limits and future work

Only synthetic English printed pages and a small number of related templates were evaluated. There is no final real-document, multipage, corrupt-input, blur or conflicting-duplicate benchmark. Development tests exercise several of those behaviors but cannot replace held-out support. Reference checking used the same agent rather than independent annotators. Most expanded development annotations remain provisional. Confidence scores and image-quality flags remain heuristic.

Future extensions could collect consented diverse local data, use independent annotation review, assess calibration and abstention costs, and compare revised preprocessing on a new untouched grouped holdout. Perspective, multilingual text and handwritten forms require separate methods and evidence. None of these extensions has been implemented or measured here.

Conclusion

ScholarReady demonstrates a reproducible local DIP and Data Science pipeline with evidence-linked readiness findings. The core experiment rejects the assumption that more preprocessing necessarily helps OCR. A performed best among A/B/C on this synthetic test, while learned A improved observed unsupported classification. Conservative rules preserved unresolved evidence and produced zero observed false-ready cases, with visible rejection errors and strict limits on generalization.
